# Deployment

## Docker on Linux

The backend needs access to the speaker's LAN. The supplied `devlop/compose.yaml` uses `network_mode: host` so discovery broadcasts originate from the host network rather than an isolated Docker bridge. An ordinary bridge with an HTTP port mapping is not an equivalent discovery setup.

```sh
mkdir -p config
cp examples/settings.json config/settings.json
docker compose -f devlop/compose.yaml up -d --build
```

All Docker files are in `devlop/`. The build context is limited to `src/`; configuration, documentation and Git metadata remain outside that context. The image contains the Python package and bundled static files only. It has no Python runtime package dependencies. It runs as an unprivileged user, with a read-only root filesystem, a small temporary filesystem, dropped capabilities, a memory limit, and rotating logs.

On a host whose checkout is owned by a user other than UID/GID 1000:

```sh
S300_UID="$(id -u)" S300_GID="$(id -g)" docker compose -f devlop/compose.yaml up -d --build
```

Keep the chosen IDs consistent between updates so saved curves remain writable.

## Reverse proxy

Forward an HTTPS virtual host to the configured backend HTTP listener on port 18730. Preserve the original `Host` header; browser writes verify that their `Origin` matches it. WebSocket forwarding is unnecessary.

In Nginx Proxy Manager, create a Proxy Host with your domain, backend address, and port; choose a valid certificate and enable Force SSL. Apply an access list appropriate for your network. Configure access restrictions and authentication in the proxy.

When the proxy runs in a bridge container and the application uses host networking, `localhost` inside the proxy container refers to that container. Use a host address reachable from the proxy, or the gateway of its Docker network. These are deployment values to inject through configuration, not values to put into source.

If the reverse proxy is the sole entry point, the application's `bind` can be set to an appropriate internal listener reachable by that proxy. Otherwise, bind to the interfaces required by your deployment. This does not change which LAN interfaces are used for speaker discovery.

The app's asset, API, manifest, and Service Worker URLs are relative to the document URL. A subpath deployment must strip the external prefix before forwarding and redirect the prefix without a trailing slash to its slash-terminated form.

## PWA and app icons

Use a valid HTTPS origin for installation and offline-shell caching. A phone's HTTP LAN address is not a secure origin; localhost exceptions do not make a remote LAN address secure.

On iPhone, open the HTTPS URL in Safari and use Share → Add to Home Screen. Enable Open as Web App if offered. No account or App Store package is involved.

The icon source is generated by `tools/generate_icons.py`. The output contains:

- Scalable SVG and 16/32/48/96/128/192/256/384/512/1024 px PNGs.
- An opaque 1024 px Apple touch icon for each of the black, white, and coffee palettes.
- Separate 512 and 1024 px `maskable` manifest entries, with artwork inside the safe central area.

The PNGs are rendered from geometry at four times their final size and downsampled once. They contain no EXIF metadata and use lossless compression. The operating system applies the app-icon mask; the PNG background fills the whole square.

The page declares a single opaque 1024×1024 Apple touch icon for the configured theme. Its URL is versioned and theme-specific, as are the favicon, install-dialog artwork, and manifest entries. Favicons and the manifest provide multiple sizes. The Service Worker precaches the current icon and removes older shell caches when it updates. If an installed iOS home-screen icon stays outdated, remove that shortcut, reload the HTTPS page, and add it again.

Only the application shell is cached. `/api/` responses, settings requests and health probes bypass the Service Worker cache. No offline write queue is implemented.

## Updates and rollback

```sh
git pull
docker compose -f devlop/compose.yaml up -d --build
```

Keep `config/` intact. Before an update, retain a source revision and a separate copy of configuration and presets. For rollback, check out the previous revision and rebuild. A Git checkout does not contain your runtime data.

`GET /healthz` checks the web service. A sleeping or disconnected speaker does not make the container unhealthy. `GET /api/state` reports the speaker connection separately.

## Connection troubleshooting

1. Confirm the backend host and the speaker are on a network where broadcast discovery can reach the speaker.
2. Check Docker host networking and any UDP 6000 filtering or Wi-Fi client isolation.
3. Wake the speaker if it has entered network standby.
4. Close unnecessary device-control clients; the speaker has limited concurrent connection slots.
5. Use `interfaces` or `broadcast_targets` only when automatic discovery needs help on a multi-interface host.

Treat packet captures and device-state dumps as private: discovery and status may include network names, device identities and MAC addresses.
